# Yangertron source feature inventory

## Evidence boundary

This is a source-only inventory for functional-clone planning. It does **not** rely on README claims, launch the upstream application, authenticate to Yandex, or test an Electron/Tauri runtime. “Observed” below means directly established by the pinned TypeScript/configuration source; it is not a claim that the remote service currently accepts or renders the behavior.

## State compatibility map

The app’s source-defined durable state is a JSON object at `<app-root>/.runtime/settings.json`, written synchronously after each mutation. Invalid/unreadable/non-object JSON becomes an empty object; individual invalid values fall back as specified below. No migration/version field or encryption is present.

| Key | Meaning | Accepted/read default | Writer |
| --- | --- | --- | --- |
| `windowBounds` | Main-window width/height | Strictly positive finite numeric `{ width, height }`; otherwise `{ width: 1280, height: 800 }` | Window resize |
| `managedMode` | Enables navigation policy, request blocker, and custom CSS | Boolean; otherwise `false` | Managed Mode menu toggle |
| `closeToTray` | Prevents ordinary window close and hides instead | Boolean; otherwise `true` | Close to Tray menu toggle |
| `showOnStartup` | Shows/focuses after first completed page load | Boolean; otherwise `true` | Show on Startup menu toggle |
| `proxyProfileId` | ID of profile to use at the next session initialization | Trimmed nonempty string or `null`; an ID absent from current `proxy.yml` is reset to `null` | Proxy radio menu/runtime validation |

Evidence: [`state/window.ts`](https://github.com/longday/yangertron/blob/c6df711b3acff9b4e6208197de93a34c9fc9da13/src/state/window.ts), [`state/helpers.ts`](https://github.com/longday/yangertron/blob/c6df711b3acff9b4e6208197de93a34c9fc9da13/src/state/helpers.ts), and [`state/proxy.ts`](https://github.com/longday/yangertron/blob/c6df711b3acff9b4e6208197de93a34c9fc9da13/src/state/proxy.ts).

## Untested assumptions, unknowns, and scope exclusions

1. **Remote-service behavior is unknown.** No Yandex login was attempted. Source inspection cannot establish current login/cookie persistence, redirects, CSP compatibility, page-title format, unread-count semantics, web calls, or whether `messenger.360.yandex.ru` currently honors the supplied user agent.
2. **Unread detection is only source-proven as a title-digit heuristic.** Its accuracy depends on the remote page title; it does not inspect a messenger API or DOM unread counter.
3. **Screen sharing is source-proven as automatic Electron source selection, not end-to-end.** Permission prompts, operating-system privacy authorization, current Electron 42 behavior, and how the Yandex page consumes the resulting stream were not run.
4. **Proxy behavior is source-proven only at Electron API boundaries.** Reachability, proxy-scheme support, challenge sequences, secure secret handling, and whether a given profile works are untested. The explicit `proxy.yml` password field is plaintext by source design.
5. **Managed Mode is narrowly defined by code.** It is not evidence that all analytics/ads/telemetry are blocked; the source recognizes only the listed hosts/path fragments and skips document frames.
6. **macOS-only clone scope excludes Linux integration.** Do not carry forward the `WebRTCPipeWireCapturer` intent as a Linux integration requirement, the NixOS/`steam-run` branch in `start.sh`, the Linux AppImage target, or `scripts/linux-install-entity.sh`. They are upstream portability/support artifacts, not requested macOS Apple Silicon behavior. Windows packaging is likewise not a clone target.
7. **No implementation decision is made here.** The inventory identifies observable upstream compatibility points only; it does not choose Tauri APIs, a persistence format, credential storage, or an app-size/RAM target.

## Concise conclusion

The source defines a single-window Yandex Messenger web wrapper with a fixed web endpoint/UA, persisted geometry and three local behavior toggles, tray/Dock state driven by a title-digit heuristic, permissive media capture, an optional hard-coded managed-mode filter/navigation policy/CSS tweak, and restart-applied proxy profiles with optional proxy-only credentials. The durable settings and exact menu defaults are clear from source; all remote Yandex behavior and runtime feasibility remain intentionally untested.
